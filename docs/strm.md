# 通过 STRM 播放 OpenList 音频

将 OpenList 生成的 `.strm` 文件放入有声书库，扫描后即可在现有播放器中播放。项目服务器按需从 OpenList 获取并流式转发音频，不会预先下载整本书；播放流量会经过项目服务器。客户端只访问项目自身的播放接口，因此不需要直接访问 OpenList 的内网地址。

## 文件组织

每个文件使用 UTF-8 编码，只包含一条 HTTP 或 HTTPS 地址。支持 UTF-8 字节序标记、首尾空白和空行，扩展名不区分大小写，文件上限为 16 KiB。暂不支持多地址播放列表、内嵌账号密码或自定义请求头语法。

```text
有声书/
└── 作者/
    └── 书名/
        ├── cover.jpg
        ├── 001.strm
        └── 002.strm
```

例如 `001.strm`：

```text
http://192.168.1.1:12345/d/quark/ITV/audiobook/书名/001.m4a
```

OpenList 导出的百分号编码地址可以直接使用，不需要手动解码。建议保留稳定的 `/d/` 地址，不要替换成它跳转后的网盘临时签名地址。播放请求每次读取本地引用文件，并重新跟随 OpenList 的跳转。

## 内网配置

项目服务器或容器必须能访问 OpenList。对于上述地址，在项目服务的环境变量中加入以下配置并重建容器：

```text
SSRF_REQUEST_FILTER_WHITELIST=192.168.1.1
```

填写主机名或 IP，不包含协议、端口和路径；多个主机用逗号分隔。如果已有白名单，请追加而不是覆盖。初始地址及每次重定向都会独立检查；若跳转到另一台内网主机，也需要明确放行该主机。无需关闭全局请求过滤。

Docker Compose 配置片段：

```yaml
environment:
  SSRF_REQUEST_FILTER_WHITELIST: "192.168.1.1"
```

修改 Compose 后，在配置文件所在目录执行 `docker compose up -d --force-recreate audiobookshelf`。仅执行 `docker restart` 或 `docker compose restart` 不会加载新环境变量。可以执行 `docker compose exec audiobookshelf printenv SSRF_REQUEST_FILTER_WHITELIST` 确认容器实际使用的值。

探测和播放使用相同的请求标识，默认是 `audiobookshelf`。若网盘要求它与取链时一致，可以用 `STRM_USER_AGENT` 环境变量指定。项目不会将用户登录令牌、浏览器 Cookie 或来源页面地址发送给 OpenList／网盘。需要额外网盘鉴权时，优先在 OpenList 中配置下载代理。

## 扫描与播放

1. 将引用文件放入有声书库并扫描。服务器通过 OpenList 探测真实音频时长、编码、标签和章节；本地文件名仍用于曲目排序。
2. 探测结果保存在书库数据库中。本地引用文件的路径、大小和修改时间与远程音频属性分别保存；普通无变化扫描不重新探测。
3. 修改引用文件后重扫，或对书籍执行重新扫描，可以更新探测结果。全库强制重新扫描也会重新探测远程音轨。
4. 探测失败的音轨保留在书籍中并记录错误；已成功获取的元数据不会因后续网络故障被清空。检查来源后重新扫描即可重试。在时长未确认或存在探测错误时，会阻止创建播放会话，避免错乱的章节与进度。

远程探测最多同时运行两个任务，每个任务最多运行 60 秒。代理的连接和无数据等待超时为 30 秒，最多跟随五次跳转。播放支持头部请求、字节范围请求和取消传输；能否正常随机拖动还取决于上游是否正确支持范围读取。播放中更换来源应指向同一份音频，若内容变化请重新扫描并重新打开播放器。

## 探测失败排查

扫描错误会保留来源故障类型，并显示相关主机或 HTTP 状态；不会输出签名查询参数、来源路径或上游错误正文。

| 日志提示 | 排查方向 |
| --- | --- |
| 内网过滤器拦截 | 将提示中的主机加入白名单，然后重建容器；跳转后的内网主机也要放行。 |
| `ECONNREFUSED` | 核对 OpenList 地址、端口、监听地址及服务状态。 |
| `ENOTFOUND`／`EAI_AGAIN` | 检查容器内的 DNS 解析。 |
| 请求超时／网络不可达 | 检查容器到 OpenList 和网盘的路由、防火墙及网络。电脑浏览器能访问不代表容器能访问。 |
| HTTP 401／403 | 检查 OpenList 下载权限、网盘授权、下载代理及 `STRM_USER_AGENT`。 |
| HTTP 404 | 检查引用的文件是否移动、删除或需要重新生成 STRM。 |
| 返回网页、文本、JSON 或播放列表 | 确认地址提供音频下载，排查登录页面及 OpenList 错误响应。 |
| FFprobe 无法识别／没有有效音轨或时长 | 检查实际返回内容、音频格式和文件是否完整。 |
| 探测超时 | 检查下载速度及来源是否支持范围读取，特别是需要读取文件尾部元数据的 M4A。 |

修正配置后，先对失败书籍执行重新扫描验证。旧版的“远程音频探测失败，请检查来源地址、网络、内网白名单及音频格式”无法区分这些原因，需要更新镜像后重新扫描才能得到具体错误。

## 首版能力

- 支持单音轨、多音轨以及与本地音轨混合的有声书，继续使用现有章节、书签和进度同步。
- 采用服务端代理播放。客户端需要能直接解码源音频；优先使用常见的 M4A／AAC 和 MP3。
- 暂不支持包含 STRM 音轨的转码、合并、音频元数据写入、整本／离线下载和订阅音频输出。相关接口会明确拒绝操作，避免误处理引用文本。
- 封面可以使用目录中的 `cover.jpg` 或现有封面管理功能；首版不从远程音频提取内嵌封面。
- 网盘账号、临时签名和下载权限由 OpenList 处理。只有已失效临时地址的引用文件，需要重新生成或更新。

## 验证

安装 Node.js 24、FFmpeg 和 FFprobe，执行：

```sh
npm ci
npm test
npm run lint
```

测试覆盖引用文件解析、内网请求过滤与跳转、范围响应、取消和超时、真实 M4A／MP3 探测、书籍持久化与失败恢复、播放会话、危险文件操作拦截及网页错误处理。未安装 FFmpeg／FFprobe 时，真实音频探测测试会跳过。

实际接入 OpenList 后，还应确认：书籍时长正确、能跨音轨播放、拖动后正常继续、关闭播放器再打开能续播。若返回上游拒绝访问，检查 OpenList 下载模式和网盘要求的请求标识；若探测失败，检查服务器到 OpenList 的连通性与白名单。
